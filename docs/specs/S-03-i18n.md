# Spec S-03: i18n

- Estado: borrador
- Fase: F1
- Módulo: M1
- Origen en Node (solo lectura): `src/core/i18n.js` (`DISCORD_LOCALES`, `clean`, `t`, `fromDiscordLocale`, `guildLanguage`, `setGuildLanguage`, `forGuild`, `list`, `localizations`, `loadLegacy`, `legacyLanguage`), `src/core/constants.js` (`EMOJI`), `languages/*.json` (23 archivos), `test/i18n.test.js`, `scripts/check-syntax.js`.

## Objetivo

Cargar los 23 idiomas al arrancar y traducir claves con variables. Elegir el idioma de cada servidor. Los textos de `languages/*.json` siguen siendo la única fuente. Esta spec no cambia ningún texto.

No incluye los comandos (S-22) ni el panel (S-24). Ahí se usan las traducciones.

## Decisiones

- Las claves de texto se comprueban con un escaneo del código, como en Node. No se usa una macro.
- Los idiomas se leen de `languages/` en disco al arrancar, para editar textos sin recompilar.
- La tabla de locales de Discord queda fija. Si Discord añade locales, se edita a mano.

## Archivos

- Crear: `rust/crates/nucleo/src/idioma.rs` (carga, `t`, limpieza y locales de Discord)
- Crear: `rust/crates/nucleo/src/idioma_servidor.rs` (idioma por servidor y lectura de v16)
- Crear: `rust/crates/nucleo/tests/idioma.rs`
- Crear: `rust/crates/nucleo/tests/claves.rs` (claves del código y de los 23 archivos)
- Crear: `rust/crates/nucleo/tests/data/t-casos.json` (generado con Node)
- Crear: `scripts/idioma-paridad-ref.js` (debe pasar `npm run lint`)
- No tocar: `languages/*.json`, `src/core/i18n.js`, `test/i18n.test.js`.

Cada archivo tiene como máximo 250 líneas.

## Contrato

- Entrada de `t`: código de idioma (nombre del archivo, por ejemplo `zh_TW`), clave con puntos (por ejemplo `buttons.skip`) y pares nombre y valor para los `{nombre}`.
- Salida de `t`: texto limpio con las variables ya sustituidas. Si la clave no existe, devuelve la clave.
- Entrada de idioma de servidor: id del servidor y locale de Discord del servidor, los dos opcionales.
- Salida de idioma de servidor: código de idioma de la lista cargada.
- Errores:
  - Falta `languages/en.json`: fallo de arranque.
  - Un JSON inválido: se registra y se omite.
  - Idioma desconocido en `set_guild_language`: error `IdiomaDesconocido`.

## Comportamiento

1. Al arrancar, lee todos los `.json` de `languages/` en orden alfabético. El código de cada idioma es el nombre del archivo: `zh_TW.json` da `zh_TW`.
2. Una clave con puntos navega objetos anidados. Si el valor no es texto, la clave no existe.
3. `t(idioma, clave, vars)`:
   a. Busca la clave en el idioma pedido.
   b. Si no está, la busca en inglés.
   c. Si tampoco está, devuelve la clave.
4. Limpieza, antes de sustituir variables:
   a. Quita los emoji con el patrón de Node: `[\p{Extended_Pictographic}\p{Regional_Indicator}\u{1F3FB}-\u{1F3FF}\u20E3\uFE0E\uFE0F\u200D]`.
   b. Cambia dos o más espacios o tabuladores seguidos por un espacio.
   c. Quita los espacios al inicio de cada línea.
   d. Recorta los espacios de los extremos.
5. Variables: `{nombre}` se sustituye si el valor existe. Si no existe, queda tal cual. Los valores sustituidos no se limpian.
6. Locales de Discord: la tabla `DISCORD_LOCALES` de Node tiene 24 entradas. Por ejemplo, `en-US` y `en-GB` dan `en`; `es-ES` y `es-419` dan `es`; `pt-BR` da `pt`; `sv-SE` da `sv`; `zh-CN` da `zh_CN`; `zh-TW` da `zh_TW`. Un locale solo se acepta si su código tiene archivo.
7. Idioma de un servidor, en este orden:
   a. El ajuste guardado en `data/guilds/<id>.json`, si el código existe.
   b. El ajuste de v16 en `database/languages.json`, si existe y el código existe. Es de solo lectura.
   c. El locale de Discord del servidor.
   d. `DEFAULT_LANGUAGE`, si existe. Si no, `en`.
8. `set_guild_language(id, código)`: rechaza códigos desconocidos. Guarda el ajuste en `data/guilds/<id>.json` sin borrar los otros campos del servidor.
9. `list()`: pares de código y `language.name`. Si falta el nombre, usa el código.
10. `localizations(clave)`: para cada locale de Discord que tenga idioma, el texto limpio recortado a 100 caracteres. Se omite `en`.
11. Los archivos de v16 se leen una vez al arrancar. Las búsquedas no tocan el disco.

## Tests

- Unitarios: interpolación; caída a inglés; clave inexistente; limpieza de emoji y espacios; locales (`tr`, `pt-BR` a `pt`, `zh-TW` a `zh_TW`, `xx` sin resultado); prioridad del idioma por servidor; `set_guild_language` rechaza `xx`; v16 con idioma válido e inválido.
- Claves (`tests/claves.rs`), con los mismos chequeos que `test/i18n.test.js`:
  - Toda clave usada en el código existe en `en.json`. El código Rust se escanea con los mismos prefijos que Node: `commands`, `buttons`, `buttonhandler`, `modalhandler`, `musicplayer`, `musicmanager`, `errors`, `ui` y `youtube`.
  - Los 23 archivos cargan y tienen `language.name`.
  - Cada idioma traduce cada clave usada. Ninguna cae a inglés.
  - Una traducción no usa variables que el inglés no tenga.
  - Ningún texto tiene emoji.
  - `errors.youtube_bot_detection` menciona `COOKIES_FILE` y `README.md`, y el README tiene ese encabezado.
- Paridad con Node: `scripts/idioma-paridad-ref.js` evalúa `t` y `clean` de Node con los casos de `t-casos.json`. Los casos incluyen emoji, espacios, variables que no existen y claves desconocidas. El test de Rust debe dar el mismo texto, byte a byte.
- Gates: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, y `npm test` sin cambios.

## Criterio de aceptación

- Los 23 idiomas cargan. `cargo test` falla si falta una clave en cualquiera de ellos.
- Los casos de `t-casos.json` dan el mismo texto que Node.
- Un servidor con ajuste de v16 conserva su idioma.
- `npm test` pasa sin cambios. `test/i18n.test.js` sigue en pie mientras exista Node.
